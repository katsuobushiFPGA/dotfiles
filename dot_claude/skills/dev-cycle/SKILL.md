このセッション自身がオーケストレータになり、1 つの実装タスクについて実装とレビューのサイクルを回します。実装は `programmer`、レビューは `code-reviewer` に委譲します（どちらも `~/.claude/agents/` にある自作エージェントです）。実装した本人とは別のコンテキストでレビューするために、コードは自分では書きません。

サブタスクへの分解が必要な大きさのタスクは、このスキルではなく `dev-cycle` エージェントに任せます。エージェント版はサブタスクごとに反復し、統合の確認まで行います。

## サイクル

1 サイクルは「`programmer` に実装または修正を委譲し、`code-reviewer` にレビューさせ、結果を評価する」です。サブエージェントはこの会話を見られないので、委譲のたびにタスク・対象ファイル・完了条件・制約をプロンプトに書きます。各サイクルの開始時に番号を示します（例: 「--- サイクル 1/3 ---」）。

レビューの指摘は次のように扱います。

- 🔴: `programmer` に修正を委譲して次のサイクルに進む。指摘は要約せず原文のまま渡す。
- 🟡 と 🟢: 対応せず、残存する指摘事項として記録する。対応を始めるとタスクの範囲が広がるためです。既存のテストを壊している 🟡 だけは修正する。
- ⚠️: 要確認事項としてレポートでユーザーに伝える。

🔴 がなくなったら終了します。サイクルは 3 回までです。3 回で 🔴 が残った場合や、同じ指摘が 2 サイクル続けて直らない場合は、同じやり方を続けても解決しない状態なので、そこで止めて残った指摘を報告します。コミットとプッシュはしません。

## 最終レポート

```
## 開発サイクル完了

### 実施サイクル数
N サイクル（🔴 が残って停止した場合はその旨）

### 最終的な変更内容
変更したファイルと概要

### 残存する指摘事項
レビューで指摘されたが修正しなかった項目とその理由
```
